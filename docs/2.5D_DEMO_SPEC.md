- 文档版本：v0.2（待评审）

- 状态：**规格阶段，未开工**
- 目标产品：单场景、单建筑、单单位的 2.5D 即时战略视觉验证 DEMO
- 目标受众：画面党、红警情怀玩家、即时战略美术爱好者
- 当前仓库：`jasonsucn/iron-dawn-rts`（私有）

## 1. 执行摘要

本 DEMO 不追求完整 RTS。它只回答一个问题：

> **用固定等距视角、分层 2D 场景、预渲染单位 Sprite 和高质量特效，能否做出“第一眼就像红警重制版概念图”、并且动起来依然有电影感的 2.5D 战场？**

首版只验证一个闭环：

1. 点击已放置的战车工厂；
2. 生产一辆坦克；
3. 坦克从工厂驶出；
4. 选中坦克，右键移动；
5. 右键装甲训练靶，炮塔转向并开火；
6. 靶标被击毁并自动重置。

在视觉资产策略上，推荐采用 **混合管线**：

- 场景、天空、地表、建筑、UI 插画：调用 DSH 的 `gpt-image` 生成，再切割、补绘、分层；
- 英雄单位的多方向、炮塔、开火与运动帧：用 3D 模型按固定镜头预渲染成 Sprite，必要时再用生图工具做单帧质感重绘。

音频资源同样由 DSH 供给：

- **环境音与战斗音效**：程序化合成 + 原创音效；
- **游戏配乐**：调用 DSH 的 `suno-music` 生成原创器乐曲，并按 DEMO 状态剪辑成动态配乐；不使用红警原作旋律。

这样既保留生图在静态美术上的高上限，又避免让生图模型直接生成大量方向帧和动画帧时出现比例、光照、武器细节漂移。所有生成资源先出小样、通过风格验收后再进入最终资产库；`suno-music` 属于付费生成能力，提交批量生成前需单独确认额度与费用。

## 2. 产品定位与边界

### 2.1 产品定位

一个**可交互的动态美术展示场景**，而不是完整游戏。

优先级从高到低：

1. 第一眼画面的完成度与氛围；
2. 10 秒动态展示中的生命感；
3. 原创、动听、能随状态变化的游戏配乐与音效；
4. 建造、移动、开火三个基础交互的手感与演出；
5. 后续内容扩展能力。

当“多做机制”与“把画面做精”冲突时，**砍机制，不降画面标准**。

### 2.2 MVP 必须包含

- 一张固定构图、可重复进入的高质量 2.5D 战场场景；
- 一座原创阵营的战车工厂；
- 一辆原创主战坦克，具备独立炮塔；
- 一个静止、可受击、可重置的装甲训练靶；
- 建造单位、移动单位、开火击毁三个基础功能；
- 用于展示画面的动态环境元素；
- 一首可循环、可随“待机/生产/开火”状态变化的原创动态配乐；
- 中文化的极简 UI；
- 可扩展到第二单位、第二建筑的数据与资产工作流。

### 2.3 MVP 明确不做

- 不做 AI 敌人、不做敌方基地、不做战斗对抗；
- 不做资源采集、经济、电力、科技树；
- 不做多人、存档、战役、地图选择；
- 不做完整寻路和复杂编队，只做单单位的点击移动与简单转向；
- 不做自由旋转镜头；
- 不做建筑自由摆放与建筑建造；
- 不做多个阵营的完整内容；
- 不接后端、不做账号系统。

## 3. 目标用户与验收北极星

### 3.1 用户

**画面党**：

- 第一眼看的是构图、光影、材质密度、动效氛围；
- 对“明显的程序化几何体”“SVG 图标”“生硬切图边缘”非常敏感；
- 不一定追求 20 种单位，但会截图、会循环看开火动画、会比较动态细节；
- 会被烟雾、尘土、金属反光、炮塔缓动、镜头呼吸和音效打动。

### 3.2 北极星指标

**指标 A：三秒截图测试**

在 1920×1080 下任意截取一个稳定帧，画面都应像一张经过排版设计的红警风概念图，而不是“网页里摆了几个模型”。

**指标 B：十秒动态测试**

连续观看 10 秒不进行任何操作，画面仍应具备：环境动态、光影变化、单位待机细节和氛围音。不能是一张静止背景上放一张 PNG。

**指标 C：交互演出测试**

完成一轮“生产 → 驶出 → 移动 → 瞄准 → 开火 → 击毁 → 重置”，每一步都要有即时视觉反馈，不能只有位置变化。

**指标 D：配乐记忆测试**

音乐不能只是无记忆点的环境铺底。至少应有一个可辨识的主题动机，并能在待机、生产、开火三种状态下产生明显但自然的情绪推进。

## 4. 垂直切片体验流程

### 4.1 首屏

场景已处于黄昏前哨状态。镜头固定，战车工厂位于左侧中景，装甲训练靶位于右前方空地。工厂初始为空载状态；首次生产完成后，坦克成为画面中心。验收截图取“坦克生产完成并停稳后”的状态，以保证画面里有完整的英雄单位。

环境动态：

- 工厂烟囱的薄烟；
- 探照灯/警示灯缓闪；
- 旗帜和电缆轻微摆动；
- 地面浮尘、远处热浪；
- 极轻的镜头呼吸和视差。

UI 只保留：

- 左上角 DEMO 标题与当前状态；
- 下方生产/选择面板；
- 右下角极小的操作提示；
- 右下或左上“重置演示”按钮。

### 4.2 生产单位

1. 点击战车工厂。
2. 工厂出现选中高亮：底部灯光增强、轮廓描边、地面范围环。
3. 下方出现一张生产卡：单位缩略图、名称、生产时间、一个“生产”按钮。
4. 点击生产，按钮变为进度条；工厂侧面警示灯开始闪，烟囱烟雾变浓，卷帘门/装配区出现动态光。
5. 生产完成后，坦克从工厂出口驶出，附带履带尘土、地面震动、轻微镜头抖动。
6. 坦克自动停在集结点，进入待机。

MVP 不代表真实经济：不扣资源、不做队列、不允许多辆同时生产，只允许一辆。

### 4.3 选择与移动

- 左键点击坦克：地面出现柔和的青色/琥珀色选择环，单位轮廓微亮，单位面板显示名称与状态。
- 右键点击地面：坦克先原地转向目标方向，再加速前进；移动过程中有履带扬尘、发动机微振、炮塔随惯性轻微摆动。
- 到达后：减速、停稳、尘土散去，状态回到待机。
- 移动采用简单转向和加减速，不做 A* 寻路、不做障碍绕行；地图上的大型静态物件用简单边界阻挡即可。

### 4.4 瞄准与开火

- 选中坦克后，右键点击装甲靶。
- 炮塔独立旋转，车体可以不动；炮塔角度有最大转速限制，避免瞬移。
- 进入射程后开火：
  - 炮口制退器火焰；
  - 炮塔后坐；
  - 车体轻微下沉；
  - 炮口烟；
  - 弹道曳光/高速弹丸；
  - 命中点金属火花、装甲碎屑、烟柱；
  - 靶标装甲变红、冒出黑烟；
  - 2–3 发后击毁，靶标坍塌并起火。
- 4 秒后训练靶自动重置，允许再次演示。
- 无反击、无命中计算悬念；伤害和击毁仅服务于视觉演出。

### 4.5 重置

“重置演示”按钮恢复：

- 工厂回到空载初始状态；
- 移除场上的坦克，允许重新演示完整生产流程；
- 训练靶满血复位；
- 清除弹坑、火焰和残留特效；
- 镜头回到初始构图。

重置后不是“把坦克传送回门口”，而是回到**未生产**的干净状态，让生产、出场、移动、开火可以反复演示。

## 6. 视觉规格

### 6.1 美术方向

关键词：

> 电影感半写实军事工业 / 黄昏边境 / 厚重金属 / 尘土与热浪 / 红警式等距战场 / 精致但不卡通

明确不做：

- 低多边形卡通；
- 像素风；
- 扁平矢量风；
- “网页 UI 贴几张 AI 图”；
- 直接用红警原作单位、建筑、标志或贴图。

画面要像**经过概念设计师统一过的 2.5D 场景**，而不是生成图片的拼贴。

### 6.2 色彩与光影

- 主光：低角度夕阳，从左上前方进入；
- 高光：暖琥珀、旧黄铜；
- 阴影：偏青、偏蓝绿，不死黑；
- 环境色：铁锈、尘土、旧混凝土、暗橄榄绿；
- 强调色：盟军/演示方的冷青色，用于选择、UI、能量反馈；
- 靶标使用橙色警示涂装，与场景形成对比；
- 全场景固定光向，所有资产必须匹配同一太阳方向。

### 6.3 构图

初始画面采用稳定的三分构图：

- 左侧：战车工厂，体量最大，形成工业化剪影；
- 中间：坦克出厂通道和空地，作为运动舞台；
- 右侧：训练靶与远景山体，作为开火视觉终点；
- 前景：低矮的岩石、电缆、沙袋或管线，形成景深；
- 远景：暖色天空、烟柱、远山或雷达剪影。

UI 不得遮挡工厂主体、坦克行进路线和靶标命中点。

### 6.4 静态画面密度

至少需要以下层级：

1. 天空/远景大气层；
2. 远山/地平线剪影；
3. 中景地形与工厂；
4. 地面细节层（轨道、碎石、油污、标识、弹坑）；
5. 单位、靶标与投影；
6. 前景遮挡物；
7. 轻雾、浮尘、热浪、暗角与色彩分级。

工厂细节要求：

- 卷帘门、通风口、管道、电缆、天线、警示灯；
- 金属板材接缝、锈迹、旧漆、编号；
- 地面混凝土基座、轮胎痕、油渍；
- 不依赖纯几何体拼装感。

坦克细节要求：

- 清晰的原创剪影；
- 履带、负重轮、装甲板、储物箱、天线、炮口制退器；
- 金属磨损、尘土、编号、阵营识别色；
- 炮塔与车体分离，炮塔可独立旋转。

### 6.5 动态设计

环境动态：

- 烟囱烟雾缓慢上升并随风偏移；
- 旗帜/电缆/布料轻微摆动；
- 警示灯呼吸闪烁；
- 浮尘颗粒在光束中漂移；
- 远景热浪扭曲；
- 极缓慢的镜头呼吸和分层视差；
- 偶尔的远处鸟群/信号灯闪动。

单位动态：

- 待机：发动机微振、天线晃动、炮塔轻微扫描；
- 移动：履带滚动感、扬尘、地面压痕、车体俯仰；
- 转向：车体先转，炮塔有轻微滞后；
- 瞄准：炮塔缓动，不瞬间吸附；
- 开火：炮口焰、后坐、烟、弹壳/制退气浪、镜头微震；
- 受击/摧毁：火花、碎片、黑烟、火焰、焦痕、坍塌。

交互动态：

- 悬停高亮；
- 选中环扩散；
- 生产进度灯的节奏变化；
- 右键移动的目的地标记；
- 按钮按下和面板出现的缓动。

### 6.6 UI 方向

- 深色军工面板，少量铜色/青色描边；
- 中文字体清晰，字号不能为了“氛围”牺牲可读性；
- 极简，不遮挡主体；
- 只展示本 DEMO 所需信息：工厂、单位、生产、状态、重置；
- UI 也有微动效：扫描线、进度光、按钮呼吸，但不能廉价闪烁；
- 所有界面文案中文，保留 IRON DAWN 品牌。

## 7. 2.5D 资产与美术管线

### 7.1 路线选择

**主路线：混合资产管线（推荐）**

| 资产类型 | 生产方式 | 原因 |
|---|---|---|
| 天空、远山、地表、氛围层 | DSH `gpt-image` 生成 + 分层切割 + 补绘 | 静态大幅画面收益最高 |
| 战车工厂 | DSH `gpt-image` 生成主体 + 分层切割 + 手动清理细节 | 单角度静态资产，生图上限高 |
| 前景道具 | DSH `gpt-image` 生成 + 切割 | 可控、可复用 |
| 英雄坦克 | DSH `gpt-image` 概念设计 → 3D 模型/预渲染 → Sprite Atlas | 8 方向、炮塔和动画必须一致 |
| 训练靶 | DSH `gpt-image` / 3D 预渲染均可 | 单角度静态受击状态 |
| 特效 | 序列帧/Shader/粒子混合 | 需要实时动态 |
| UI 图标/缩略图 | DSH `gpt-image` + 切图 + 统一二次处理 | 视觉统一，成本低 |
| 动态配乐 | DSH `suno-music` 生成 + 剪辑/循环处理 | 提供主题动机和状态段落 |

**备选路线：纯生图 Sprite**

仅适用于：

- 固定视角、4 方向、简化动作；
- 能接受大量手动修图和方向不一致风险；
- 预算有限但只做静态展示优先。

不作为正式版本主方案。

### 7.2 gpt-image 资产流程

以下流程通过 DSH 的 `gpt-image` 执行：

1. 先确定镜头、光向、色板、分辨率基准；
2. 用同一套风格提示词生成场景、建筑、道具参考；
3. 生成时保留 2 倍分辨率余量；
4. 背景移除/分割，拆成主体、阴影、前景、发光层；
5. 手动修补切图边缘、白边、颜色溢出；
6. 统一色温、对比度和光向；
7. 输出 PNG/WebP 资产和锚点信息；
8. 通过“100% 放大检查”后才允许进入游戏。

每张生成图都必须通过：

- 光向一致；
- 比例与场景匹配；
- 无文字乱码；
- 无明显 AI 结构错误；
- 切图边缘无白边/彩边；
- 不包含受版权保护的红警原作元素。

### 7.3 单位 Sprite 流程

1. 根据 DSH `gpt-image` 生成的概念图确定坦克剪影、材质和识别特征；
2. 建立 3D 模型，固定太阳方向和正交渲染相机；
3. 车体与炮塔分开材质和渲染层；
4. 车体渲染 8 个朝向；
5. 炮塔渲染 16 个朝向或 8 个朝向的细分补间；
6. 渲染待机、移动、开火关键帧；
7. 逐帧检查履带、炮管、天线和比例；
8. 生成透明背景帧、独立阴影层、团队色蒙版；
9. 打包成 Atlas，记录锚点、朝向、帧率和炮塔挂点。

### 7.4 切割与 Atlas 规范

- 所有单位帧按脚底/履带接地点设置统一锚点；
- 建筑按占地中心设置锚点；
- 阴影单独一层，不烘死在主体 alpha 中；
- 纹理使用 WebP + alpha，必要处保留 PNG；
- 单张 Atlas 不超过 4096×4096；
- 生成 `metadata.json`，包含帧坐标、动作、方向、帧率、锚点；
- 所有资产命名使用英文小写+下划线，显示名中文化；
- 每次替换资产必须经过资产检查清单。

### 7.5 Sprite 数量基准

首版单单位建议：

| 内容 | 最小规格 |
|---|---|
| 车体待机 | 8 方向 × 4 帧 |
| 车体移动 | 8 方向 × 8 帧 |
| 炮塔 | 16 方向静态帧 |
| 开火演出 | 程序化后坐 + 炮口特效 + 少量关键帧 |
| 阴影 | 8 方向或程序化投影 |
| 死亡/残骸 | 1–2 个状态，残骸可作为静态装饰 |

首版允许用程序化后坐、炮口闪光的叠加来减少帧数，但不能出现炮塔瞬移或方向跳变。

### 7.6 DSH 资源供给与生成工具链

本项目的图像与音乐资源由 DSH 内置能力供给，不依赖外部设计师先交付整套素材：

| 资源 | DSH 能力 | 用途 | 产出 |
|---|---|---|---|
| 静态视觉 | `gpt-image` | 天空、远景、地表、建筑概念与主体、道具、UI 插画、缩略图 | PNG/WebP + 分层切图 |
| 游戏音乐 | `suno-music` | 原创主题音乐、待机/生产/战斗/收束段落 | WAV/MP3/OGG + 循环点 |
| 程序化音效 | WebAudio | 炮击、履带、伺服、环境风声 | 运行时合成 |
| 英雄单位帧 | Blender/Three.js 预渲染 | 8 方向车体、16 方向炮塔、动作帧 | PNG 序列 → Atlas |

#### 7.6.1 图像生成规范

- 调用 DSH 的 `gpt-image`，先做 1–2 张风格小样，锁定色板、光向和镜头后再批量生成；
- 所有背景、建筑和道具使用**同一风格参考图**和一致的镜头语言；
- 生图阶段只生成“单角度静态资产”，不承担单位的 8 方向动画帧；
- 生成结果必须经过背景切割、白边/彩边修补、光向校正和人工筛选；
- 每张最终图保存生成记录：提示词、模型、参考图、日期、用途；
- 禁止生成或使用红警原作单位、建筑、标志、UI 或受版权保护的素材。

#### 7.6.2 动态音乐设计

音乐由 DSH 的 `suno-music` 生成，目标是**原创、动听、有主题记忆点**的器乐配乐，而不是一条循环 pad 或红警原作旋律的仿制品。

首版生成四个可拼接的配乐段落：

| 段落 | 触发状态 | 音乐方向 | 时长建议 |
|---|---|---|---|
| `ambient` | 首屏/无操作 | 低音弦乐、工业低频脉冲、稀疏金属质感 | 45–75 秒循环 |
| `production` | 工厂生产 | 机械节拍、上升固定音型、警示性铜管点缀 | 30–60 秒循环 |
| `combat` | 首次开火 | 强化打击乐、低铜管、紧张的十六分音符推进 | 45–75 秒循环 |
| `resolve` | 靶标击毁/重置 | 短促的解决和弦、余响、回到待机氛围 | 8–15 秒尾奏 |

为保持“像一首曲子”而不是四段无关音乐：

- 统一调性（建议 D 小调）与统一动机；
- 四段共享一个 4–6 音的主题动机；
- BPM 在段落间保持可对齐关系，建议 72 / 96 / 120；
- 全部为器乐，不使用人声；
- 生成 2–3 个候选版本，经过试听后选择；
- 不引用红警原作旋律，不使用原作音效。

#### 7.6.3 动态音乐运行方式

音频导演根据 DEMO 状态切换，不采用“单曲循环 + 调音量”的假动态：

- **待机**：`ambient`；
- **点击生产**：在大约 2 秒内交叉淡入 `production`；
- **首次开火**：切换到 `combat`，炮声出现时音乐自动压低，避免盖住音效；
- **靶标摧毁**：播放 `resolve`，随后回到 `ambient`；
- **重置**：立即淡出战斗音乐，回到待机主题；
- 所有切换在小节线上对齐，使用 1.5–2.5 秒交叉淡化，避免硬切；
- 音频预加载，循环点做采样级无缝处理；
- 音乐总线、音效总线分开，炮击期间音乐做短暂 ducking；
- 若 Suno 产物无法提供可靠分轨，则以**独立段落交叉淡化**为主，不强行做 stem 拆分。

#### 7.6.4 付费、审批与可追溯

- `suno-music` 是**付费生成能力**。每次提交音乐生成前必须单独向用户确认，不明文默认扣费；
- 每批生成前说明预计生成数量、候选数量与成本，生成后报告实际消耗；
- `gpt-image` 生成同样按批次控制，先小样后终稿，避免无意义重复生成；
- 正式资产只保留经筛选的版本，同时保留提示词、模型、日期和来源记录；
- 规格阶段**不调用、不生成、不保存**任何付费素材；当前文档只是资源计划。

#### 7.6.5 资源目录

```text

    image-source/          # 生成小样与保留的原始图
    prompts/               # 提示词、模型和生成记录

    music/
      ambient.ogg
      production.ogg
      combat.ogg
      resolve.ogg
    sfx/                   # 炮击、履带、伺服、环境音
```

### 8.1 总体结构

建议作为现有仓库中的独立子项目：

```text

  index.html
  assets/
    scenes/
      outpost-dusk/
        background.webp
        midground.webp
        foreground.webp
        atmosphere.webp
    buildings/
      war_factory/
    units/
      vanguard_tank/
    effects/
    ui/
  data/
    scene.json
    buildings.json
    units.json
  src/
    main.js
    render/
      SpriteScene.js
      SpriteAnimator.js
      DepthSorter.js
      CameraRig.js
      Effects.js
    game/
      BuildController.js
      UnitController.js
      TurretController.js
      TargetDummy.js
    audio/
      AudioDirector.js
    ui/
      ShowcaseHUD.js
  tools/
    pack-atlas.mjs
    validate-assets.mjs
```

不直接改造现有完整 RTS 主流程，避免破坏已交付版本；后续验证成功后再决定是否吸收到主游戏。

### 8.2 渲染技术

- Three.js（沿用项目现有版本）；
- 正交相机，固定等距视角；
- 分层平面 + Sprite；
- 分层顺序：
  1. 天空/远景；
  2. 地面；
  3. 地面细节与阴影；
  4. 建筑；
  5. 单位；
  6. 前景遮挡；
  7. 特效；
  8. 泛光/暗角/色彩分级；
  9. DOM UI；
- 单位、建筑按世界 Z/屏幕 Y 做深度排序；
- 固定镜头意味着可以大量烘焙光照、阴影和反射；
- 动态光照仅用于炮口闪光、爆炸、警示灯等局部效果；
- 后处理建议：轻泛光、色彩分级、暗角、极轻微颗粒/热浪；
- 避免过度景深和过度抖动，保证可读性。

### 8.3 交互与仿真

- 输入：鼠标点击/右键、极少量键盘快捷键；
- 地面拾取：正交相机射线投影到地平面；
- 单位移动：目标点、转向角速度、线速度、加减速曲线；
- 炮塔：独立目标角、最大角速度、缓动；
- 开火：冷却计时、射程判断、炮口特效、飞行物/命中点判定；
- 靶标：HP、受击表现、摧毁状态、定时重置；
- 生产：按钮触发、进度、完成回调、出场动画、状态恢复；
- 不做 AI、经济、编队、资源、战争迷雾。

### 8.4 音频导演

- 音乐：`suno-music` 生成的原创器乐段落，由 `AudioDirector` 按待机/生产/开火/收束切换；
- 环境：风声、远处工业低鸣、金属热胀冷缩、鸟鸣；
- 工厂：机械运转、警示灯蜂鸣、卷帘门和液压声；
- 坦克：发动机低鸣、履带沙沙声、炮塔伺服；
- 开火：炮击、制退气浪、弹壳落地、命中金属；
- 音频总线：Music / SFX / UI 分离，炮击时音乐 ducking；
- 音乐切换对齐小节，使用交叉淡化；循环点必须无缝；
- 音效尽量程序化或原创，不直接使用游戏原作音效。

音乐不是附加项，而是“动听 DEMO”的 P0 验收内容：需要能被记住的主题动机，以及至少三种可感知的状态变化。

### 9.2 新增内容流程

新增第二辆坦克或第二座建筑时，应该只需要：

1. 产出资产；
2. 按固定命名与锚点规范整理；
3. 在对应 JSON 中登记；
4. 重新生成 Atlas；
5. UI 自动根据配置展示新内容；
6. 不需要修改渲染核心、输入系统或主循环。

如果新增内容需要修改核心渲染代码，则视为扩展工作流失败。

### 9.3 扩展优先级

首版通过验收后，再按以下顺序扩展：

1. 第二单位（例如轻型侦察车）；
2. 第二建筑（例如兵营）；
3. 多种开火特效和命中反馈；
4. 简单多单位选择；
5. 两个阵营的外观变体；
6. 再考虑是否回到完整 RTS。

## 10. 性能与质量预算

### 10.1 性能目标

- 设计分辨率：1920×1080；
- 目标帧率：主流桌面独立显卡 60 FPS；
- 最低可接受：30 FPS，且不能出现输入延迟感；
- 首次本地加载目标：< 8 秒；
- 纹理显存目标：< 256 MB；
- 音乐从首次交互进入后 1 秒内可听，循环点无爆音、无静音间隙；
- 页面无控制台错误、无 404、无未处理异常。

### 10.2 资产预算

- 初始资源体积目标：< 50 MB；
- 其中音乐资源目标 < 12 MB，优先 OGG/Opus，MP3 兜底；
- 单张背景不超过 4096×2160；
- 单张单位 Atlas 不超过 4096×4096；
- 使用 WebP/VP8/PNG 按资产类型选择；
- 不允许为了“高清”无节制堆 8K 贴图；
- 生成但未选用的候选图/音乐不得进入最终包。

### 10.3 代码质量

- 所有资源通过 manifest 加载；
- 不使用硬编码的资产路径散落在业务代码中；
- 交互、渲染、内容配置三层分离；
- 无外部 CDN 依赖；
- 静态 HTTP 服务即可运行；
- 所有中文文案集中在配置/文案层。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 生图方向/比例不一致 | 坦克转向时穿帮 | 单位采用 3D 预渲染，生图只做概念和质感参考 |
| 切图白边、彩边 | 一眼看出是贴图 | 2 倍分辨率、去背景、去色溢出、人工修补、阴影分层 |
| 光向不统一 | 画面拼贴感 | 先定光位和色板，所有资产生成后统一检查 |
| 建筑与单位比例错误 | 2.5D 空间感崩塌 | 使用统一瓦片尺度、锚点和镜头校准图 |
| 遮挡/深度排序错误 | 单位穿过建筑 | 固定镜头 + Y 排序 + 前景遮挡层 |
| 资产过大 | 加载慢、掉帧 | Atlas、WebP、纹理预算、按需加载 |
| 纯生图导致扩展困难 | 每新增内容都要大改 | 固定资产规范、数据驱动、Atlas 流水线 |
| 音乐生成结果不搭片 | 氛围出戏 | 同一调性/动机批量生成候选，先试听再定稿 |
| 音乐段落切换生硬 | 破坏沉浸感 | 小节对齐、交叉淡化、统一 BPM/调性、循环点预检 |
| 生成服务产生费用 | 预算不可控 | 每批生成前确认数量与费用；Suno 生成必须单独获批 |
| 生成素材权利不清 | 公开使用风险 | 只使用原创提示词，避免原作旋律/素材，保存生成记录和授权条款 |
| 范围膨胀 | 画面验证变完整游戏 | 本规格书即范围边界，机制优先级低于画面 |

## 14. 待确认决策

开工前需要确认以下事项：

1. **资产路线**：是否采用“生图场景/建筑 + 3D 预渲染单位”的混合方案？
2. **镜头**：是否固定等距视角、不允许旋转？推荐固定，以便把画面打磨到极致。
3. **建筑状态**：首版战车工厂是否预置在场景中，不做建筑自由放置？
4. **单位数量**：首版是否严格只有一辆“先锋主战坦克”？
5. **美术方向**：是否接受“电影感半写实”，而不是卡通或像素风？
6. **目标硬件/浏览器**：基准是否为 1920×1080、主流桌面 Chrome/Edge？
7. **动态配乐**：是否采用 `suno-music` 生成原创器乐主题，并实现待机/生产/开火/收束四段动态切换？
8. **生成预算**：是否批准 `gpt-image` 和 `suno-music` 的分批生成额度；每批生成前是否会单独确认？
9. **音乐风格**：偏好“管弦+工业电子”的电影感配乐，还是更接近经典 RTS 的铜管进行曲？
10. **音乐使用范围**：仅用于本地 DEMO，还是也计划用于公开演示/宣传片？

## 15. 结论

技术路线可行，但成败不在 2.5D 渲染本身，而在资产生产纪律。

- **可以做**：固定等距镜头、分层场景、预渲染单位 Sprite、实时 VFX、动态音乐、数据驱动扩展；
- **不建议做**：纯靠生图生成所有方向帧和动画帧，再直接切割上线；也不建议用一条循环曲假装动态配乐；
- **建议做**：用 DSH 的 `gpt-image` 负责场景和建筑，3D 预渲染负责单位与炮塔，用 DSH 的 `suno-music` 生成原创动态配乐；统一锚点、光向、Atlas、音乐状态和扩展规范。

本规格书通过评审后，下一步应先做 **S1：单帧视觉定调**，用一张静态画面锁定镜头、构图、光色和资产比例；同时可以用 `suno-music` 生成一段主题小样试听，但在获得明确的付费生成确认前，不调用音乐生成。
